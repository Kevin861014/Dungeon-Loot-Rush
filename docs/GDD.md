# 遊戲設計文件(GDD)

---
## 1. 遊戲概述
### 1.1 遊戲類型
Rogue-like 地牢探索 + 裝備養成,搖桿移動 + 自動攻擊 + 主動技能。
### 1.2 平台
Android / iOS,使用 Unity 開發,單機 + 廣告變現(無需伺服器)。
### 1.3 核心賣點
- 單局制地牢挑戰,死亡即結算,獎勵帶回主城養成裝備
- 房間結構模板化 + 內容隨機化,兼顧開發成本與重玩新鮮感
- 武器彈道特性(單發/扇形/彈射/貫穿)提供操作變化,天賦數值提供長線深度
- 廣告觸點自然嵌入(死亡復活、寶箱加速),不強迫插播
### 1.4 參考對象
《元氣騎士 Soul Knight》(戰鬥/地牢結構)、《Archero》《菇勇者傳說》(輕度自動戰鬥+裝備養成)
---
## 2. 核心遊戲迴圈(Game Loop)
```
進入地牢 → 探索房間(戰鬥/商人/寶箱/事件)→ 抵達下一層入口
    ↓
第4關為 Boss 房 → 擊敗或死亡
    ↓
死亡或通關 → 結算本次獲得的資源/寶箱 → 回到主城
    ↓
主城:開寶箱 → 取得材料/裝備詞綴 → 強化裝備/點天賦
    ↓
變強後再次進入地牢,挑戰更深的層數
```

## 3. 地牢結構
### 3.1 樓層與關卡編排
- 每「層」包含 4 小關 + 1 Boss 關(即第4關為 Boss)
- 通過 Boss 後進入下一層,層數理論上可持續遞增(隨層數提升怪物強度與掉落品質)
### 3.2 房間結構(每小關內部)
- 每小關(非 Boss 關)由 **4-5 個房間** 組成,採「房間圖」結構
- 房間類型:
  - **戰鬥房**(必經,含隨機怪物)
  - **下層入口房**(每小關僅 1 間,通往下一關/下一層)
  - **商人房**(機率出現,販售本局限定道具,使用地牢內金幣購買)
  - **額外寶箱房**(機率出現,內含加碼寶箱)
  - **事件房**(選配,可留待後期擴充,如陷阱/祝福/詛咒抉擇)
### 3.3 地圖生成邏輯(關鍵技術決策)
**採用「模板庫 + 內容隨機化」而非完全隨機生成演算法**,原因:降低路徑連通性演算法的開發與除錯成本,同時維持重玩新鮮感。
- **房間連接骨架**:事先設計 15-20 組固定房間佈局模板(如一字型、Y字分岔、十字型),每次進入小關時隨機抽取一組模板
- **模板保底規則**:模板需保證「入口→出口」至少有一條可行走路徑,商人房/寶箱房不得阻擋主路徑
- **房間內部隨機化**(維持新鮮感的核心手段):
  - 房間內預先定義「進入點」「出口點」及兩者間的**保底可通行路徑**
  - 怪物不寫死位置,改為預先標記 5-8 個「候選生成點」,每次隨機抽取 3-5 個點生怪
  - 場景障礙物/裝飾物從模組化小道具庫中隨機挑選,僅擺放於保底路徑以外區域
- 此方式讓同一套房間骨架,因怪物配置、裝飾物、寶箱是否出現而產生視覺與戰鬥體感差異,不需完全隨機生成演算法

## 4. 戰鬥系統
### 4.1 操作方案:搖桿移動 + 自動攻擊 + 主動技能(方案 B)
- **移動**:畫面左下角虛擬搖桿,8 方向自由移動,用於閃避怪物攻擊、走位
- **普通攻擊**:全自動,角色自動朝最近敵人開火/揮砍,攻速由裝備決定,玩家無需手動瞄準
- **技能鍵**:畫面右下角 1-2 個按鈕,主動施放特殊技能(範圍傷害/特殊彈道/爆發輸出),具備冷卻時間
### 4.2 傷害判定
- 採用「接觸傷害」邏輯,不做複雜招式判定:
  - 近戰怪:進入其攻擊範圍即扣血
  - 遠程怪:發射彈道,玩家碰撞箱命中即扣血
  - 玩家攻擊同理,彈道/範圍命中怪物即造成傷害
### 4.3 死亡與復活機制
- 玩家 HP 歸零時彈出選擇:**看廣告復活(原地滿血或半血繼續)** 或 **放棄本局,直接結算**
- **每趟地牢挑戰,廣告復活次數上限為 3 次**,超過上限後死亡即直接結算,無法再復活
- 復活後怪物血量/場景狀態維持死亡當下(不重置房間)
### 4.4 回血機制
- **擊殺回血**:怪物有機率掉落「血包」拾取物,碰觸即回一定比例血量
- **裝備被動回血**:部分裝備詞綴自帶每秒回血或攻擊吸血效果(與強化系統掛鉤)
- 不設計主動治療技能,以降低系統複雜度,回血動機導向「裝備養成」
---
## 5. 結算制度(Run-based)
- 採用 **Rogue-like 單局結算制**,而非逐層回城制
- 玩家從進入地牢起,持續挑戰直到死亡(復活次數用盡)或主動放棄,才會觸發結算
- 結算內容:本局所有已收集的金幣、材料、寶箱、裝備詞綴,一次性帶回主城
- 主城內進行裝備強化、天賦分配,完成後再次挑戰新的一局
**選擇理由**:相較逐層回城制,結算制心理張力更強(玩家需抉擇「要不要繼續冒險」)、開發邏輯更單純(無需做中途存檔/斷點續玩的狀態管理)、且死亡的挫折感更直接導向「看廣告復活」的動機。

## 6. 裝備與養成系統
### 6.1 裝備強化(分層強化系統)
- 裝備非「換新即淘汰舊裝」,而是**同一件裝備持續疊加強化等級**(如 1-99 級)
- 強化曲線分段設計:
  - 低等級(1-10):僅需金幣即可強化
  - 中等級(11-30):需金幣 + 強化石
  - 高等級(31+):需突破材料,且有失敗機率風險
- 強化等級提升武器基礎數值(攻擊力、攻速、防禦等)
### 6.2 裝備彈道特性(詞綴系統)
裝備附帶「彈道行為」詞綴,決定武器的實際打法,是驚喜感與重玩性的核心來源:
- 單發直線
- 扇形多發
- 彈射(碰牆/碰敵反彈)
- 貫穿(打穿一整排敵人)
- 追蹤(自動鎖定最近敵人,稀有詞綴)
詞綴隨寶箱開啟隨機獲得,稀有度分級對應詞綴強度與特殊程度。
### 6.3 天賦系統(獨立於裝備的角色成長線)
- 天賦為長期投入資源慢慢點出的被動加成(攻擊力%、移速%、暴擊率%等)
- 與裝備彈道特性分工:**裝備決定「怎麼打」,天賦決定「數值多強」**,兩條線互相獨立又疊加
- 初期版本可採「升級隨機 3 選 1 被動」的輕量模式(降低 UI 與美術開發成本)
### 6.4 武器基礎類型(可選擴充,非必要於第一版)
- 弓 / 法杖 / 槍等不同基礎武器類型,提供攻速與外觀差異
- 建議第一版先做 1-2 種基礎武器 + 詞綴系統驗證好玩度,之後再擴充武器種類

## 7. 寶箱與資源系統
### 7.1 地牢內寶箱(即時開啟)
- 定位:地牢探索中拾取的寶箱,強調**即時反饋**,不宜有長時間等待
- 開啟方式:立即開啟或極短動畫等待(數秒),不使用「看廣告加速」機制
- 稀有度(銅/銀/金/傳說)體現在**掉落內容品質**,非等待時間長短
### 7.2 主城寶箱(等待制,對應廣告觸點)
- 定位:結算後帶回主城的戰利品箱、或每日簽到箱等「非探索中」情境
- 銅/銀/金/傳說寶箱對應不同開啟等待時間(如 5 分鐘 / 30 分鐘 / 2 小時 / 6 小時)
- 玩家可選擇等待,或**看廣告立即開啟**(廣告觸點 2)
### 7.3 商人房機制
- 地牢內機率出現的房間,販售本局限定道具/臨時強化
- 使用地牢內累積金幣購買,離開本局後失效,與主城永久養成系統區隔開,避免玩家混淆資源用途

## 9. 美術風格與資源策略
### 9.1 開發階段策略
- **第一階段(原型驗證期)**:使用純色塊/簡單幾何圖形代替美術,優先跑通所有系統邏輯(戰鬥、房間生成、寶箱、強化),確認好玩度與數據
- **第二階段(美術置換期)**:驗證玩法後,採購 Unity Asset Store / itch.io 現成像素風 Roguelike 素材包置換,快速獲得統一風格且品質穩定的視覺呈現
- **第三階段(可選,長期投入後)**:若數據證明值得長期經營,再考慮 AI 生成客製美術或外包,建立差異化風格
### 9.2 素材需求清單(供日後採購/生成參考)
- 角色行走/攻擊/受傷/死亡動畫(建議 4 或 8 方向)
- 怪物種類數種,含普通與 Boss 差異化外觀
- 地牢磚塊/牆壁/地板貼圖(需模組化拼接)
- 武器圖示與彈道特效(對應各詞綴視覺表現)
- 寶箱(銅/銀/金/傳說)開啟動畫
- UI 元素:搖桿、技能鍵、血條、寶箱倒數、結算畫面

## 10. 技術棧建議
- **引擎**:Unity(跨平台輸出 Android/iOS,廣告 SDK 生態成熟)
- **廣告中介平台**:建議採用 LevelPlay(IronSource)或 AppLovin MAX,可同時串接多廣告來源競價,收益優於單一廣告網路
- **iOS 打包**:需 Mac 環境(或雲端 Mac 服務)進行 Xcode 打包上架
- **Unity 授權**:年收入低於門檻可使用 Unity Personal(免費版),現階段足夠使用
